# Проверка библиотеки

## Автономные тесты OneScript

Требуется OneScript 2.1. Сторонние пакеты и платформа 1С не нужны.
Из каталога библиотеки:

```powershell
oscript '.\tests\ТестыБиблиотеки.os'
if ($LASTEXITCODE -ne 0) { throw 'Тесты библиотеки не пройдены' }
```

Можно запускать и из другого рабочего каталога, передав полный путь к тесту.
При успехе выводится `PASS` с количеством проверок, при ошибке — код выхода 1.
Эти тесты не подключаются к сети и не выполняют операций с ИБ.

Проверяются:

- Загрузка пакета с русскими именами через относительный путь.
- Контракты всех 19 адресов: HTTP-тип, точный путь, query, JSON, обязательные поля.
- Секрет в заголовке, отсутствие токена в query/теле.
- Строгая обработка `0/00.00` и ошибок, включая `00.01` и таймаут KillSession.
- GUID в `result`, параметр `guid`, `update_date` и статусы `0/-1/1/2`.
- Ожидание, ошибка задачи и общий таймаут без повторной отправки POST.
- UTF-8, BOM, ISO-даты, булевы, валидация параметров, UNKNOWN/HTML-ответы.
- Логирование, маскирование секретов, комментарий Jenkins, UNC-путь.

## Настоящий HTTP на локальном mock-сервере

Дополнительно нужен Python 3.10+. Других Python-пакетов нет.

```powershell
python -B '.\tests\http_mock.py' --oscript 'C:\OneScript_2\bin\oscript.exe'
```

Скрипт поднимает временный сервер на `127.0.0.1` и свободном порту, запускает
OneScript, проверяет фактически принятые запросы и завершает сервер.
Проверяет GET/POST, кодировки запросов и ответов, header token, настоящие JSON boolean,
числовые флаги восстановления, статусы `1 → 2 → 0`, запрет HTTP redirect.
Рабочий оркестратор не используется. Прямой `ТестHTTP.os` отклоняет адреса
вне локального `127.0.0.1`.

## Проверка на работе: сначала чтение

Запускайте от той же учётной записи, от которой работает Jenkins-агент.
Значение токена передаётся только через `withCredentials`:

```groovy
withCredentials([string(credentialsId: 'erp-restore-api-token',
                        variable: 'MECHEL_API_TOKEN')]) {
    bat '@chcp 65001 >nul\n@"C:\\OneScript_2\\bin\\oscript.exe" ".\\Скрипты\\Примеры\\ПроверитьАПИ.os"'
}
```

Перед запуском задайте `MECHEL_API_URL` и `MECHEL_TEST_INFOBASE` под ваш стенд.
Путь команды приведён для рабочего каталога `НоваяАвтоматизация`.
Пример читает список агентов и параметры блокировки тестовой ИБ;
ничего не блокирует и не восстанавливает.

Если HTTP 401/403 — проверьте УЗ агента и авторизацию публикации. Если HTTP 200
с ошибкой API — смотрите `code`/`description` и права токена.
Не подменяйте токен его именем credentials.

## Следующая проверка: эмуляция восстановления

После успешного чтения используйте пример из [справочника](СПРАВОЧНИК.md)
с `test=1`, заранее выбранными источником и тестовым приёмником.
API.md описывает эмуляцию длительностью 300 секунд.

Ожидается:

1. Ответ `new`: GUID в `result`.
2. Запрос `status` с этим `guid`.
3. `1` — выполнение, возможный `2` — пауза, `0` — успешное завершение.
4. `update_date` сохраняется в возвращаемой структуре статуса.

Далее отдельно на тестовой базе проверяются блокировка/разблокировка,
одиночный сеанс и реальное восстановление с `test=0`.
Перед разблокировкой учитывайте исходное состояние: `СнятьБлокировку`
задаёт флаги явно, а не восстанавливает снимок старых параметров.

Для будущего массового завершения сеансов нужен обезличенный пример `GetSessions`.
Для будущей настройки одного пользователя нужны выбранное имя и способ входа
в ИБ после восстановления. Эти данные не требуется придумывать в библиотеке.
