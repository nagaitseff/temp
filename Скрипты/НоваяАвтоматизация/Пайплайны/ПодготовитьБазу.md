# Подготовить базу в Jenkins

1. Скопируйте [ВосстановитьИБ.os](../Скрипты/ПодготовкаИБ/ВосстановитьИБ.os)
   и [ЗапуститьОбработкуИБ.os](../Скрипты/ПодготовкаИБ/ЗапуститьОбработкуИБ.os) в
   `C:\OneScript_2\api` на Windows-агенте с OneScript 2.1 и `mechel2 2.0.2`.
2. Укажите [ПодготовитьБазу.Jenkinsfile](ПодготовитьБазу.Jenkinsfile) в джобе
   Pipeline. Подойдёт текст Jenkinsfile или Pipeline script from SCM.
3. Выберите в `TOKEN` Secret Text `erp-restore-api-token`. Источник можно
   задать по имени ИБ. Для существующего приёмника укажите полный адрес,
   например `UKM-SAPP145:6541|ERP_DEV_EXAMPLE`.

| Параметр | Что делает |
|---|---|
| `RESTORE_MODE=restore` | Восстановление по умолчанию. Содержимое приёмника заменяется копией источника |
| `RESTORE_MODE=wait` | Опрос ранее созданной заявки по `RESTORE_GUID` |
| `BRANCH_NAME` | Имя ветки ERP, например `hotfix/2.5.27.107`. Если поле пустое, обработку берём из `develop` |
| `MAKE_COPY` | По умолчанию используется доступная копия. Установите флаг для новой копии источника |
| `ENTERPRISE_USER` | Пользователь 1С для входа в приёмник и запуска обработки (ключ `/N`). При пустом поле используется аутентификация Windows под учёткой агента |
| `WAIT_TIMEOUT_MINUTES` | Сколько ждать результата. По умолчанию 120 минут, опрос раз в минуту |

Для checkout используется `http://UKM-SAPP115/mechel/erp.git` и Jenkins
credential `JenkinsReader`. Переменные `MECHEL_ERP_DIR` и `MECHEL_ERP_COMMIT`
доступны следующим стейджам в той же сборке.

### Восстановление и запуск обработки

До отправки заявки Jenkins проверяет адрес приёмника, наличие `1cv8.exe`
версии `8.3.27.2342` и `tools/OS/fm_release.epf` из checkout.

Сразу после успешного восстановления Jenkins запускает `1cv8.exe ENTERPRISE`
на приёмнике с `/Execute` и ждёт завершения 1С. Созданием пользователей,
установкой паролей и закрытием клиента управляет сама обработка. Учётка запуска должна иметь доступ к
восстановленной ИБ и право выполнять обработку. При ненулевом коде 1С или
таймауте в 30 минут этап завершается ошибкой. Лог платформы `fm-release.log`
сохраняется в артефактах при его наличии.
[Параметры запуска 1С](https://1c-dn.com/library/tutorials/1c_enterprise_administrator_guide_file_mode_8_3_27/).

Сборка CF/CFE и обновление ИБ будут добавлены после обработки.

### Заявка оркестратора

После отправки заявки GUID появится в консоли и описании сборки. По завершении
джобы его можно скачать из артефакта `restore-guid.txt`. Статус `0` означает
успех восстановления, `-1` означает ошибку, `1` и `2` продолжают ожидание.
Таймаут Jenkins или OneScript не отменяет заявку оркестратора.
[Как Jenkins хранит артефакты](https://www.jenkins.io/doc/pipeline/steps/core/#archiveartifacts-archive-the-artifacts).

При остановке Jenkins запустите `wait` с сохранённым GUID. Этот режим только
проверяет статус заявки. Если ответ на создание заявки потерян до получения
GUID, найдите заявку в оркестраторе
по комментарию `Jenkins: job=<имя> #<номер>`. Маркер `.pending` удерживает
повторную отправку из того же каталога сборки.

Блокировками при восстановлении управляет оркестратор.

Локальная проверка из папки `НоваяАвтоматизация` использует временный
HTTP-сервер и вымышленные ИБ.

```powershell
python -B '.\Скрипты\ПодготовкаИБ\tests\test_restore.py' --oscript 'C:\OneScript_2\bin\oscript.exe'
```
